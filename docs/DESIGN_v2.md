## 1. 背景

- PC向けDAWは高機能だが、導入・操作のハードルが高い。
- スマホでふと思いついたフレーズをすぐ形にできる、インストール不要のブラウザ完結型ツールが欲しい。
- Web Audio APIの発展により、ブラウザだけで音の合成・再生・書き出しが可能になっている。

## 2. 目的

スマホのブラウザだけで、ドラムとシンセによるループ曲を作り、保存・書き出しできるDTMウェブアプリ(アプリ名:pocket-loop、仮)を開発する。

## 3. ゴール / 目標

| 区分 | 内容 |
|---|---|
| 最終ゴール | スマホで曲の骨組み(ループ)を作り、WAVで書き出せる |
| MVPゴール | 起動後 **30秒以内** に最初の音が鳴り、1分以内にビートが組める |
| 品質目標 | 中堅スマホで音切れなしに再生(ドラム4+シンセ1トラック) |
| 運用目標 | 外部通信なし(完全ローカル動作) |

### MVP(Minimum Viable Product)とは

**「最小限の機能で価値を検証できる、最初の動くバージョン」** のことです。全機能を作り込んでから公開するのではなく、核となる体験だけを先に作って実際に触り、評価してから拡張します。

- 目的:「作る価値があるか」「スマホで気持ちよく操作できるか」を早く確かめる
- 利点:手戻りが小さい。音の遅延やタッチ操作といった最大のリスクを早期に検証できる
- 本件でのMVP:**ステップシーケンサーでビートを組み、再生し、保存できる** ところまで(詳細は 7.4)

## 4. 前提条件 & 制約

### 前提
- 対象:スマホのモダンブラウザ
  - **iPhone:iOS 16以上**(iPhone 8以降が目安)
  - **Android:Android 10以上、Chrome最新版、RAM 3GB以上**
- 実機テストの基準は、2〜3年前の中級機種とする(最新機種だけで動いても、古めの機種で音切れすることがあるため)
- 手持ちにない機種は無理に対象へ入れず、「動作確認済み機種」として後から増やす
- 縦持ち中心、横持ちにも対応
- ユーザーはDTM未経験者を含む

### 制約(スマホ特有)
- **音声の自動再生制限**:最初のタップで AudioContext を開始する必要がある
- **iOS**:マナースイッチで音が出ない場合がある → 初回に案内表示
- **Web MIDI は iOS Safari 非対応** → MVPでは対象外
- **性能**:トラック数・エフェクト数に上限を設ける
- **タッチ操作**:ボタンは最小 44×44px、ホバー操作に依存しない
- **バックグラウンド**:別アプリに切り替えると音声が停止し得る
- **外部通信なし**:CDN・解析・テレメトリを使わない

## 5. 結論

- **技術**:TypeScript + Vite + React、音声は Web Audio API + Tone.js(npmでバンドル)
- **保存**:IndexedDB(プロジェクトをJSONで保存)
- **配布**:PWA(ホーム画面追加、オフライン動作)
- **ホスティング**:GitHub Pages(GitHub Actionsで自動公開)
- **ライセンス**:MIT(公開リポジトリ)
- **方針**:MVPは「ドラム+シンセ1種のステップシーケンサー」に絞り、ピアノロール以降は段階的に追加する

## 6. リスク & 課題

| # | リスク | 影響 | 対策 |
|---|---|---|---|
| R1 | 再生遅延・音切れ | 体験品質の低下 | lookahead スケジューリング(Tone.Transport)。バッファ設定を調整 |
| R2 | iOSで音が出ない | 利用不能に見える | 初回タップで resume、マナースイッチ案内を表示 |
| R3 | スマホの処理性能不足 | 動作が重い | トラック/エフェクト数の上限、実機での性能計測 |
| R4 | 小画面での操作性 | 誤タップ・入力困難 | 大きめのステップボタン、タッチ操作の実機テスト |
| R5 | 保存データの消失 | 作品が失われる | JSONの書き出し/読込、ストレージ永続化の要求(`navigator.storage.persist`) |
| R6 | ピアノロールの小画面UI | 開発の難度が高い | Phase 2で別途UI設計。MVPには含めない |
| R7 | 音源の品質 | 音がチープに聞こえる | 合成ドラムの調整。サンプルは同梱し外部取得しない |
| R8 | 公開リポジトリでコードが誰でも読める | 複製・流用される | MITライセンスで方針を明示。秘密情報は置かない。将来の収益化を考える場合は公開前に見直す |

## 7. 詳細

### 7.1 リポジトリ・公開・ライセンス

| 項目 | 内容 |
|---|---|
| リポジトリ | `nimonit1/pocket-loop-app`(公開) |
| ホスティング | GitHub Pages(GitHub Actionsで `main` へのpushごとに自動公開) |
| 公開URL(想定) | `https://nimonit1.github.io/pocket-loop-app/` |
| ライセンス | MIT。範囲は自作コードのみ |
| アプリ名 | pocket-loop(仮)。公開前に既存アプリ・商標との重複を検索で確認する |
| ビルド設定 | 相対パス出力のため、リポジトリ名やURLが変わっても影響しない |

**ライセンスの注意点**
- 同梱するサンプル音源・フォント・画像は、それぞれ別のライセンス確認が必要。
- 現状は音をWeb Audioで合成するため、外部の音源は使っていない。
- 依存ライブラリを追加するときは、ライセンスを確認する。

### 7.2 開発体制

- 開発:Claudeのクラウドセッションで、コード作成・ビルド・テスト・コミット・pushまでを行う。
- ブランチ運用:作業用ブランチ(`claude/...`)へpushし、Pull Request経由で `main` にマージする。
- 実機確認:クラウド環境ではスマホの音を確認できないため、公開URLをスマホで開いて結果を報告する。
- 確認項目:初回タップで音が出るか、遅延・音切れ、5分連続再生、iOSのマナースイッチ、タップのしやすさ。

### 7.3 外部通信の確認

| 項目 | 結果 |
|---|---|
| 外部API呼び出し | なし |
| CDN / 外部ライブラリの動的読込 | なし(Tone.jsはnpmでバンドル) |
| 外部フォント | 使用しない(端末フォント) |
| 解析・トラッキング・ログ送信 | なし |
| マイク録音(Phase 5) | ブラウザ内で処理。サーバー送信なし |
| 依存パッケージのテレメトリ | フェーズ0のビルド成果物で、外部URLへの通信先がないことを確認済み |

※アプリ本体の初回配信(ホスティングからのダウンロード)のみが通信で、以降はPWAとして完全オフライン動作(PWA化はMVPで実装)。

### 7.4 MVPの範囲

**含める**
- 16ステップのシーケンサー(縦持ちで操作可能なグリッド)
- ドラム4トラック(キック / スネア / ハイハット / クラップ)、合成音源
- シンセ1トラック(単音、音階を選べる簡易入力)。音色は1種類で、波形(ノコギリ波 / 矩形波 / サイン波)のみ切り替え可能
- BPM設定(60〜200)、再生 / 停止
- トラックごとの音量 / ミュート
- プロジェクトの自動保存と読込(IndexedDB)
- PWA対応(ホーム画面追加)

**含めない(次フェーズ以降)**
- ピアノロール、複数パターン、ミキサーのエフェクト
- 音色プリセットの追加(ピアノロールと一緒に検討)
- WAV書き出し、マイク録音、Web MIDI
- テンプレート曲

**MVPの合否基準**
1. iPhoneとAndroidの実機で、タップ後すぐ再生できる
2. 5分連続再生しても音切れ・フリーズがない
3. ブラウザを閉じて再度開いても作品が復元される

### 7.5 画面設計(スマホ縦持ち)

```
┌──────────────────┐
│ ▶/■   BPM 120  ⋯ │ ヘッダー(再生・BPM・メニュー)
├──────────────────┤
│ キック   ■□□□■□□□ … │
│ スネア   □□□□■□□□ … │ ステップグリッド
│ ハット   ■□■□■□■□ … │ (8ステップ×2段)
│ クラップ □□□□□□□□ … │
│ シンセ   ♪ ♪   ♪   … │
├──────────────────┤
│ 音量 / ミュート    │ トラック設定(ボトムシート)
└──────────────────┘
```

- 親指で届く下部に主要操作を配置
- ステップはタップでON/OFF、長押しで詳細(ベロシティ)
- 再生位置を示すインジケータ

### 7.6 アーキテクチャ

```
UI (React)
  ├─ プロジェクト状態 (Zustand等の軽量ストア)
  ├─ 音声エンジン (Tone.js: Transport / Synth / Sampler)
  └─ 永続化 (IndexedDB)
```

- UIと音声エンジンを分離し、UIの再描画が再生に影響しないようにする
- プロジェクトはJSON(tracks / steps / bpm / version)で表現し、将来のスキーマ変更に備え version を持たせる

### 7.8 フェーズ0の実装メモ

**実装した範囲**
- Vite + React + TypeScript + Tone.js の構成
- 合成ドラム4種、再生/停止、BPM(60〜200、5刻み)
- 16ステップを8個×2段にしたグリッド(1個44px以上)
- 初回の「再生」タップで音声を開始し、iPhone向けにマナースイッチの案内を表示
- 画面下に遅延情報(状態・サンプルレート・baseLatency・outputLatency)を表示。実機確認の報告用
- GitHub Actionsによる自動公開設定

**設計上の判断(実機確認の結果で見直す)**
- lookAhead(先読み時間)は 0.05 秒。反応を優先した値で、音切れが出る場合は大きくする
- 画面が隠れたら自動で停止し、画面の表示と音声の状態を揃える
- ステップの入力は、スクロール操作での誤入力を避けるため、タップ(クリック)で判定する

**未確認**
- 実機での音の鳴り方(遅延・音切れ・iOSの挙動)は未確認。ビルドと外部通信の確認のみ済み
