## 1. 背景

- PC向けDAWは高機能だが、導入・操作のハードルが高い。
- スマホでふと思いついたフレーズをすぐ形にできる、インストール不要のブラウザ完結型ツールが欲しい。
- Web Audio APIの発展により、ブラウザだけで音の合成・再生・書き出しが可能になっている。

## 2. 目的

スマホのブラウザだけで、ドラムとシンセによるループ曲を作り、保存・書き出しできるDTMウェブアプリ(アプリ名:pocket-loop、仮)を開発する。

## 3. ゴール / 目標

| 区分 | 内容 |
|---|---|
| 最終ゴール | スマホで曲の骨組み(ループ)を作り、WAVで書き出せる |
| MVPゴール | 起動後 **30秒以内** に最初の音が鳴り、1分以内にビートが組める |
| 品質目標 | 中堅スマホで音切れなしに再生(ドラム4+シンセ1トラック) |
| 運用目標 | 外部通信なし(完全ローカル動作) |

### MVP(Minimum Viable Product)とは

**「最小限の機能で価値を検証できる、最初の動くバージョン」** のことです。全機能を作り込んでから公開するのではなく、核となる体験だけを先に作って実際に触り、評価してから拡張します。

- 目的:「作る価値があるか」「スマホで気持ちよく操作できるか」を早く確かめる
- 利点:手戻りが小さい。音の遅延やタッチ操作といった最大のリスクを早期に検証できる
- 本件でのMVP:**ステップシーケンサーでビートを組み、再生し、保存できる** ところまで(詳細は 7.4)

## 4. 前提条件 & 制約

### 前提
- 対象:スマホのモダンブラウザ
  - **iPhone:iOS 16以上**(iPhone 8以降が目安)
  - **Android:Android 10以上、Chrome最新版、RAM 3GB以上**
- 実機テストの基準は、2〜3年前の中級機種とする(最新機種だけで動いても、古めの機種で音切れすることがあるため)
- 手持ちにない機種は無理に対象へ入れず、「動作確認済み機種」として後から増やす
- 縦持ち中心、横持ちにも対応
- ユーザーはDTM未経験者を含む

### 制約(スマホ特有)
- **音声の自動再生制限**:最初のタップで AudioContext を開始する必要がある
- **iOS**:マナースイッチで音が出ない場合がある → 初回に案内表示
- **Web MIDI は iOS Safari 非対応** → MVPでは対象外
- **性能**:トラック数・エフェクト数に上限を設ける
- **タッチ操作**:ボタンは最小 44×44px、ホバー操作に依存しない
- **バックグラウンド**:別アプリに切り替えると音声が停止し得る
- **外部通信なし**:CDN・解析・テレメトリを使わない

## 5. 結論

- **技術**:TypeScript + Vite + React、音声は Web Audio API + Tone.js(npmでバンドル)
- **保存**:IndexedDB(プロジェクトをJSONで保存)
- **配布**:PWA(ホーム画面追加、オフライン動作)
- **ホスティング**:GitHub Pages(GitHub Actionsで自動公開)
- **ライセンス**:MIT(公開リポジトリ)
- **方針**:MVPは「ドラム+シンセ1種のステップシーケンサー」に絞り、ピアノロール以降は段階的に追加する

### 7.2 開発体制

- 開発:Claudeのクラウドセッションで、コード作成・ビルド・テスト・コミット・pushまでを行う。

- 実機確認:クラウド環境ではスマホの音を確認できないため、公開URLをスマホで開いて結果を報告する。
- 確認項目:初回タップで音が出るか、遅延・音切れ、5分連続再生、iOSのマナースイッチ、タップのしやすさ。

### 7.4 MVPの範囲

**含める**
- 16ステップのシーケンサー(縦持ちで操作可能なグリッド)
- ドラム4トラック(キック / スネア / ハイハット / クラップ)、合成音源
- シンセ1トラック(単音、音階を選べる簡易入力)。音色は1種類で、波形(ノコギリ波 / 矩形波 / サイン波)のみ切り替え可能
- BPM設定(60〜200)、再生 / 停止
- トラックごとの音量 / ミュート
- プロジェクトの自動保存と読込(IndexedDB)
- PWA対応(ホーム画面追加)

**含めない(次フェーズ以降)**
- ピアノロール、複数パターン、ミキサーのエフェクト
- 音色プリセットの追加(ピアノロールと一緒に検討)
- WAV書き出し、マイク録音、Web MIDI
- テンプレート曲

**MVPの合否基準**
1. iPhoneとAndroidの実機で、タップ後すぐ再生できる
2. 5分連続再生しても音切れ・フリーズがない
3. ブラウザを閉じて再度開いても作品が復元される

### 7.5 画面設計(スマホ縦持ち)

```
┌──────────────────┐
│ ▶/■   BPM 120  ⋯ │ ヘッダー(再生・BPM・メニュー)
├──────────────────┤
│ キック   ■□□□■□□□ … │
│ スネア   □□□□■□□□ … │ ステップグリッド
│ ハット   ■□■□■□■□ … │ (8ステップ×2段)
│ クラップ □□□□□□□□ … │
│ シンセ   ♪ ♪   ♪   … │
├──────────────────┤
│ 音量 / ミュート    │ トラック設定(ボトムシート)
└──────────────────┘
```

- 親指で届く下部に主要操作を配置
- ステップはタップでON/OFF、長押しで詳細(ベロシティ)
- 再生位置を示すインジケータ
- (フェーズ2)シンセトラックは、トラック名の横に波形選択・削除ボタンを並べ、その下に音階選択(8列×2行)・ステップグリッドを配置する。複数トラック時は同じ構成を縦に繰り返す
- (フェーズ3)トラック設定の各行に「▾」ボタンを追加し、タップで展開するとパン・EQ(低/中/高)・リバーブ送り・ディレイ送りのスライダーが現れる(折りたたみ式)。各スライダーをすばやく2回タップすると初期値に戻る(7.13参照)

### 7.6 アーキテクチャ

```
UI (React)
  ├─ プロジェクト状態 (Zustand等の軽量ストア)
  ├─ 音声エンジン (Tone.js: Transport / Synth / Sampler)
  └─ 永続化 (IndexedDB)
```

- UIと音声エンジンを分離し、UIの再描画が再生に影響しないようにする
- プロジェクトはJSON(tracks / steps / bpm / version)で表現し、将来のスキーマ変更に備え version を持たせる
- (フェーズ3)各トラックの音声経路は「[楽器] → EQ3 → Channel(音量/パン/ミュート) → master」。リバーブ・ディレイは共有の1系統のみ生成し、各トラックから送り量(センド)で混ぜる

### 7.8 フェーズ0の実装メモ

**実装した範囲**
- Vite + React + TypeScript + Tone.js の構成
- 合成ドラム4種、再生/停止、BPM(60〜200、5刻み)
- 16ステップを8個×2段にしたグリッド(1個44px以上)
- 初回の「再生」タップで音声を開始し、iPhone向けにマナースイッチの案内を表示
- 画面下に遅延情報(状態・サンプルレート・baseLatency・outputLatency)を表示。実機確認の報告用
- GitHub Actionsによる自動公開設定

**設計上の判断(実機確認の結果で見直す)**
- lookAhead(先読み時間)は 0.05 秒。反応を優先した値で、音切れが出る場合は大きくする
- 画面が隠れたら自動で停止し、画面の表示と音声の状態を揃える
- ステップの入力は、スクロール操作での誤入力を避けるため、タップ(クリック)で判定する

**実機確認の結果**
- スマホ実機で音が鳴ることを確認済み(2026-10-27)。詳細な遅延・音切れの計測は今後のフェーズ確認時にあわせて行う

### 7.9 フェーズ1の実装メモ

**実装した範囲**
- シンセ1トラック(単音、`Tone.Synth`)。音階はハ長調1オクターブ(C4〜C5)から選んで配置する簡易入力。波形はノコギリ波 / 矩形波 / サイン波を切り替え可能(初期値:ノコギリ波)
- トラックごとの音量(0〜100%のスライダー)とミュート(ドラム4+シンセ1の計5トラック)。ヘッダーの「⋯」から開くボトムシート(トラック設定)にまとめた
- プロジェクトの自動保存:BPM・パターン・波形・音量・ミュートの変更を検知し、0.5秒後にIndexedDBへ保存。起動時に読み込んで復元する。保存データの形が壊れている場合は初期状態で起動する(読み込み失敗時もアプリは使える)
- R5対策として `navigator.storage.persist()` を要求(ブラウザが許可した場合のみ有効。拒否されても動作に支障はない)
- PWA対応:`manifest.webmanifest` とアイコン(ビルド環境でローカル生成したPNG。外部画像・外部APIは未使用)、サービスワーカーで同一オリジンのみをキャッシュ(オフライン時はキャッシュへフォールバック)。ホーム画面に追加できる

**設計上の判断**
- シンセの音階入力は、ピアノロールではなく「音階を選んでからステップをタップ」という簡易方式にした(7.4の「含めない」範囲のピアノロールとは区別)
- 音量はdBではなく0〜100%の線形スライダーで提供し、内部でTone.jsのdBに変換している(直感的な操作を優先)
- トラック設定はボトムシートにまとめ、メイングリッドは操作を増やさずシンプルに保った(7.5の画面設計どおり)
- サービスワーカーはビルド時のハッシュ付きファイル名に依存しない方式(ネットワーク優先・取得成功時にキャッシュへ保存、失敗時はキャッシュを返す)にして、実装をシンプルにした

**実機確認の結果**
- スマホ実機で確認し、合否基準3点を含めすべてOK(2026-10-28)。シンセ音・音量/ミュート操作・PWAのホーム画面追加/オフライン動作・5分連続再生・作品の復元について、特に問題の報告はなし

### 7.10 フェーズ2の範囲

**含める**
- シンセトラックの追加/削除(最大3トラックまで。ドラム4+シンセ最大3の計7トラックが上限。R3の性能対策)
- 音階の範囲をフェーズ1の1オクターブ(ハ長調)から2オクターブ(C3〜C5、ハ長調15音)に拡張
- シンセトラックごとに波形(ノコギリ波 / 矩形波 / サイン波)を個別設定
- クオンタイズ(分解能)選択:1/8・1/16(初期値)・1/32。プロジェクト全体(ドラム・シンセ共通)に適用
- フェーズ1の保存データ形式からの自動移行

**含めない(次フェーズ以降)**
- グリッド外への自由な音符配置、ドラッグによる音符の長さ変更(引き続きステップへのタップ入力のみ)
- 複数パターン、ミキサーのエフェクト
- WAV書き出し、マイク録音、Web MIDI

**UI設計上の判断(R6対応)**
- R6(ピアノロールの小画面UIは開発難度が高い)への対応として、時間軸を横に伸ばし横スクロールで操作する従来型のピアノロールは採用しなかった。横スクロールはフェーズ0の時点で「誤入力を避けるため採用しない」と決めており、その方針を踏襲した
- 代わりに、フェーズ1の「音階を選んでからステップをタップする」という操作を、音階の範囲拡大・トラックの複数化という形でそのまま拡張した。画面幅は増やさず、8列グリッドが自動で複数行に折り返す実装(音階選択・ステップ入力とも)を維持した

### 7.11 フェーズ2の実装メモ

**実装した範囲**
- シンセトラックを配列で管理し、「+ シンセを追加」「✕(削除)」で増減できるようにした(最大3トラック)
- 音階をC3〜C5(ハ長調2オクターブ、15音)に拡張。音階選択UIは8列×2行に自動で折り返す
- トラックごとの波形選択をトラックヘッダー内(トラック名の隣)に配置。ミキサーのボトムシートとは独立させた
- クオンタイズ(1/8・1/16・1/32)をボトムシートに追加。切り替え時は既存パターンを切り詰め/0埋めして引き継ぐ
- 保存データのバージョンをv2に更新。v1(フェーズ1)で保存されたデータを起動時に自動変換する処理を追加(既存ユーザーの作品が消えないようにするため)

**設計上の判断**
- 複数シンセトラックの内部管理は、固定添字の配列ではなくID(`crypto.randomUUID()`)をキーにした。音量/ミュートもトラックIDをキーとする辞書に変更し、トラックの増減に対応しやすくした
- クオンタイズは「既存の音符を保ったまま切り詰め/0埋め」とし、音符の移動・補間は行わない(単純で分かりやすい挙動を優先)
- 性能上限(R3)として、シンセトラックは最大3つまでに制限(ドラム4+シンセ3=最大7トラック)

**実機確認の結果**
- スマホ実機で確認し、特に問題の報告はなし(2026-10-30)。シンセトラックを複数追加した状態での音切れ、クオンタイズ切替の操作感、フェーズ1データからの自動移行について、いずれもOK

### 7.12 フェーズ3の範囲

**含める**
- トラックごとのパン(左右の定位、-100〜100)
- トラックごとの3バンドEQ(低音/中音/高音、各-12〜+12dB)
- リバーブ・ディレイへの送り量(センド、0〜100%)をトラックごとに設定。リバーブ・ディレイ本体は共有の1系統のみ(R3対策、7.6参照)
- トラック設定(ボトムシート)の各行を折りたたみ式にし、「▾」でパン/EQ/センドの詳細を展開
- フェーズ2の保存データ形式からの自動移行(エフェクト設定は初期値で補う)

**含めない(次フェーズ以降)**
- リバーブ・ディレイ本体のパラメータ調整(ルームサイズ、ディレイタイム、フィードバック量など)。現時点では固定値
- トラックごとに個別のリバーブ/ディレイを持たせること(R3により共有バス方式を採用)
- コンプレッサーなど、EQ・リバーブ・ディレイ以外のエフェクト

**アーキテクチャ上の判断(R3対応)**
- リバーブ(`Tone.JCReverb`)とディレイ(`Tone.FeedbackDelay`)は、畳み込み処理のいらない軽量な実装を選び、プロジェクト全体で1つずつだけ生成した。トラック数が増えてもエフェクトのインスタンス数は変わらない
- 各トラックはEQ3通過後に「ドライ(Channel)」「リバーブ送り」「ディレイ送り」の3方向へ分岐させるだけなので、トラック1つあたりの追加ノード数は一定に保たれる

### 7.13 フェーズ3の実装メモ

**実装した範囲**
- 音声エンジンに、トラックごとのEQ3・パン(Channel内蔵)・リバーブ/ディレイ送り用Gainを追加。ドラム・シンセ共通の仕組みにした
- トラック設定(ボトムシート)の各行に展開ボタンを追加し、タップでパン・EQ(低/中/高)・リバーブ送り・ディレイ送りのスライダーを表示する折りたたみUIにした
- 保存データのバージョンをv3に更新。v2(フェーズ2)で保存されたデータを起動時に自動変換する処理を追加(エフェクト設定がない場合は初期値で補う)

**設計上の判断**
- トラックごとのエフェクト設定は`TrackEffects`という1つの型にまとめ、音量/ミュートと同様にトラックID(またはドラムの`drum0`など)をキーとする辞書で管理した
- パンは`Tone.Channel`に標準で備わる機能を利用し、新しいノードを増やさなかった(性能面でも有利)
- EQの範囲は-12〜+12dBとし、極端な設定で音が歪みにくいようにした

**実機確認の結果**
- スマホ実機で確認し、特に問題の報告はなし(2026-10-30)。複数トラックでパン・EQ・リバーブ/ディレイ送りを使った場合の音切れ、折りたたみ式ミキサーUIの操作感、フェーズ2データからの自動移行、いずれもOK

**追加対応:スライダーのダブルタップリセット(ユーザー要望)**
- 音量・パン・EQ(低/中/高)・リバーブ/ディレイ送りの各スライダーを、すばやく2回タップ(ダブルタップ)すると初期値に戻るようにした
- モバイルブラウザでは`dblclick`イベントが安定して発火しない場合があるため、`click`イベントの発生タイムスタンプを比較する自前のダブルタップ判定を実装した(350ミリ秒以内の連続タップで判定)
- 音量の初期値はトラックごとの既定値(ドラムは個別の既定音量、シンセは75%)、パン・EQ・センドは0に戻す
- トラック設定シートに「スライダーをすばやく2回タップすると、初期値に戻ります」という案内文を追加した

**実機確認の結果(ダブルタップリセット)**
- スマホ実機で確認し、特に問題の報告はなし(2026-10-30)。ダブルタップでスライダーが初期値に戻る操作感はOK
